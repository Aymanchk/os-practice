## Как запустить

Нужна Ubuntu (или WSL на Windows), Python 3.11 или новее и Git.

**1. Установить пакеты и скачать репозиторий**

```bash
sudo apt update
sudo apt install -y git python3 python3-matplotlib strace shellcheck procps
git clone https://github.com/Aymanchk/os-practice.git
cd os-practice
```

**2. Запустить работу**

Каждая работа запускается одной командой, скриптом `run.sh` в её папке. Скрипт можно вызывать из любой папки:

```bash
./practical-05/run.sh
./modul1/run.sh
```

Все восемь практических подряд:

```bash
for n in 1 2 3 4 5 6 7 8; do ./practical-0$n/run.sh; done
```

Что нужно каждой работе:

| Пакет | Для чего |
| --- | --- |
| `python3` | все работы (проверено на Python 3.14, нужен 3.11+) |
| `procps` | команда `ps` в ПР-3 (в обычной Ubuntu уже есть) |
| `strace` | трассировка системных вызовов в ПР-2 |
| `python3-matplotlib` | PNG-график в ПР-5 (без него работает всё, кроме графика) |
| `shellcheck` | необязательно: проверка bash-скриптов |

**Windows.** В PowerShell от имени администратора выполнить `wsl --install -d Ubuntu`, после перезагрузки открыть Ubuntu из меню Пуск и выполнить команды выше. Команды вводятся в терминале Ubuntu, а не в PowerShell. Репозиторий лучше клонировать в домашнюю папку WSL (`~`), а не в `/mnt/c/...`: там права файлов и скорость работают как в Linux.

**macOS.** Работы делались в виртуальной машине [UTM](https://mac.getutm.app/) с Ubuntu для ARM64. Второй вариант: Docker Desktop.

```bash
docker run --rm -it --shm-size=512m -v "$PWD":/work -w /work ubuntu:26.04 bash
apt-get update && apt-get install -y python3 python3-matplotlib strace procps
./practical-05/run.sh
```

## Заметки

- ПР-1 проверяет настройки самой системы (пользователь `student2`, каталог `/srv/shared`). Как их создать, написано в разделе «Как повторить настройку» [README ПР-1](practical-01/README.md). В Docker-контейнере ПР-1 не имеет смысла.
- `--shm-size=512m` нужен для ПР-7: по умолчанию Docker даёт `/dev/shm` всего 64 МБ, а замер передаёт 80 МБ. Без флага эти замеры будут пропущены с сообщением.
- Числа замеров времени (ПР-4, ПР-7) на другом компьютере будут немного другими, но соотношения сохраняются.
- Графики и трассировки: `practical-05/rr_quantum.png` (Round Robin), `practical-02/trace.txt` и `trace_cat.txt` (полные трассировки `strace`).

## Словарик

| Термин | Что это |
| --- | --- |
| Ядро (kernel) | Главная часть ОС, которая управляет процессором, памятью и устройствами и работает в привилегированном режиме. |
| Системный вызов | Запрос программы к ядру выполнить то, что ей самой запрещено (открыть файл, создать процесс). |
| `strace` | Утилита, которая показывает все системные вызовы программы. |
| Права доступа | Кто (владелец, группа, остальные) может читать, писать и запускать файл или заходить в каталог. |
| `sudo` / `su` | `sudo` выполняет одну команду с правами другого пользователя, `su` переключает на другого пользователя целиком. |
| Процесс | Запущенная программа вместе со всем её состоянием: памятью, открытыми файлами, регистрами. |
| PID / PPID | Номер процесса и номер его родителя. |
| `fork` | Системный вызов, который создаёт копию текущего процесса (ребёнка). |
| `exec` | Системный вызов, который заменяет программу внутри процесса на другую. |
| `wait` | Системный вызов, которым родитель дожидается ребёнка и забирает его код завершения. |
| Зомби | Завершившийся процесс, код которого родитель ещё не забрал через `wait`. |
| Сирота | Процесс, родитель которого завершился раньше; его усыновляет PID 1 или subreaper. |
| Copy-on-Write | После `fork` память не копируется сразу: страница копируется только при первой записи в неё. |
| Поток (thread) | Независимая линия выполнения внутри процесса; потоки одного процесса делят память. |
| GIL | Глобальная блокировка интерпретатора CPython: Python-код одновременно исполняет только один поток. |
| Планировщик | Часть ОС, которая решает, какой процесс сейчас получит процессор. |
| Квант | Отрезок времени, который Round Robin даёт процессу перед переключением на следующий. |
| Голодание | Процесс бесконечно не получает ресурс, потому что его всё время обгоняют другие. |
| Старение | Постепенное повышение приоритета ждущего процесса, чтобы он не голодал. |
| MLFQ | Несколько очередей с разными квантами: новый процесс начинает наверху, длинный опускается вниз. |
| Состояние гонки | Ошибка, когда результат зависит от того, в каком порядке потоки случайно выполнились. |
| Критическая секция | Участок кода, работающий с общими данными, где одновременно должен быть только один поток. |
| Мьютекс | Замок: захватил один поток, остальные ждут, пока он не освободит. |
| Семафор | Счётчик с операциями «уменьшить, а при нуле ждать» и «увеличить». |
| Условная переменная | Позволяет потоку заснуть до наступления условия, временно отпустив мьютекс. |
| Барьер | Точка, где потоки ждут друг друга, пока все не дойдут до неё. |
| IPC | Межпроцессное взаимодействие: способы обмена данными между процессами. |
| Pipe | Однонаправленный канал байтов между родственными процессами. |
| FIFO | Именованный канал: как pipe, но с именем в файловой системе, доступен любым процессам. |
| Unix-сокет | Двусторонний канал между процессами одной машины через файл-сокет. |
| Разделяемая память | Участок памяти, видимый сразу нескольким процессам; самый быстрый IPC, но синхронизация на программисте. |
| Сигнал | Короткое асинхронное уведомление процессу (например, SIGINT по Ctrl+C), без данных. |
| Взаимоблокировка (deadlock) | Несколько потоков ждут ресурсы друг друга, и ни один не может продолжить. |
| Граф ожидания | Граф «кто кого ждёт»; цикл в нём при единичных ресурсах означает deadlock. |
| Алгоритм банкира | Выдаёт ресурс, только если после этого система остаётся в безопасном состоянии. |

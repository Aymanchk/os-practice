## Задание

Написать Bash-скрипт, который считает сообщения ERROR и WARN по модулям.
Добавить проверку аргументов и режим `--top N`. Написать Python-программу
для чтения файла и сравнить её системные вызовы с командой `cat`.

## Файлы

- `gen_logs.py` — генератор исходных журналов.
- `data/` — 50 сгенерированных журналов.
- `report.sh` — отчёт по уровням ERROR и WARN.
- `hello.py` — чтение файла и вывод его размера.
- `trace.txt` — трассировка Python-программы.
- `trace_cat.txt` — трассировка `cat`.

## Как запустить

Команды выполняются в терминале Ubuntu из папки `practical-02`:

```bash
python3 gen_logs.py
./report.sh data ERROR --top 3
./report.sh data WARN
python3 hello.py data/01.log
```


Проверка ошибочных аргументов:

```text
$ ./report.sh
Ошибка: неверное число аргументов
Использование: ./report.sh <каталог> <ERROR|WARN> [--top N]
$ echo $?
1

$ ./report.sh /nope ERROR
Ошибка: каталог не существует: /nope
Использование: ./report.sh <каталог> <ERROR|WARN> [--top N]
$ echo $?
1

$ ./report.sh data INFO
Ошибка: уровень должен быть ERROR или WARN
Использование: ./report.sh <каталог> <ERROR|WARN> [--top N]
$ echo $?
1

$ ./report.sh data ERROR --top abc
Ошибка: N должно быть положительным целым числом
Использование: ./report.sh <каталог> <ERROR|WARN> [--top N]
$ echo $?
1
```

Команды `bash -n report.sh` и `shellcheck report.sh` завершились без ошибок.

## Системные вызовы

Трассировки получены на Ubuntu Desktop ARM64:

```bash
strace -f -y -o trace.txt python3 hello.py data/01.log > /dev/null
strace -f -y -o trace_cat.txt cat data/01.log > /dev/null
```

Параметр `-y` показывает путь файла рядом с его дескриптором.

| Программа | Всего системных вызовов |
| --- | ---: |
| `python3 hello.py data/01.log` | 407 |
| `cat data/01.log` | 144 |

В трассировке Python-программы **3 вызова `read` относятся к `data/01.log`**.
Первый прочитал 19076 байт, следующие два вернули 0 при проверке конца файла.

Python-программа выполнила на 263 системных вызова больше, чем `cat`.
Основная причина — запуск интерпретатора: загрузка библиотек и модулей,
проверка путей и настройка памяти. Остальные вызовы не следует считать
только «лишними»: среди них есть открытие и закрытие нужного файла,
а также вывод результата. `cat` выполняет ту же задачу с меньшим объёмом
подготовительной работы.

## Контрольные вопросы

**Почему пользовательская программа не может обратиться к диску напрямую?**

Программа работает в пользовательском режиме. Доступ к устройствам
контролирует ядро, чтобы программы не обходили права доступа и не
повреждали данные друг друга. Программа запрашивает работу с файлом
через системные вызовы.

**Что дороже: вызов функции или системный вызов?**

Обычно системный вызов дороже. При нём процессор переходит в режим ядра,
ядро проверяет запрос, затем управление возвращается программе.
Обычный вызов функции остаётся в пользовательском режиме.
